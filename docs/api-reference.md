# API Reference

All endpoints are served under `http://<host>:8000`. Interactive, always-current
schemas are generated by FastAPI:

- **Swagger UI** — `/docs`
- **ReDoc** — `/redoc`
- **OpenAPI JSON** — `/openapi.json`

This page is a hand-curated map of the surface. For exact request/response models,
prefer `/docs` (it never drifts from the code).

---

## Search

### `POST /api/v1/search`

Structured hybrid search. Body is a `SearchRequest`:

| Field | Type | Notes |
|---|---|---|
| `knowledge_type` | `alarm\|setup\|experience\|null` | `null` searches all types |
| `project` | `str\|null` | Exact-match filter (taxonomy) |
| `equipment` | `str\|null` | Exact-match filter (taxonomy) |
| `error_codes` | `list[str]` | Doc matches if it contains any one |
| `keywords` | `list[str]` | BM25 keywords |
| `query_text` | `str\|null` | Raw text for the vector pass |
| `mode` | `auto\|strict\|loose\|vector_only` | Default `auto` |
| `size`, `from_` | `int` | Paging; bounded by `max_result_window` |

Returns a `SearchResponse` with `status`, `total`, `hits[]`, `effective_params`,
optional `facets` + `facets_truncated` (on `too_many`), and a `banner` (on
`loose_hit` / `vector_only`). See the [status contract](architecture/search-ranking.md#status-contract).

## Chat & extract

Both require `KB_LLM__API_KEY` (else **503**). See [AI Chat Search](architecture/ai-chat.md).

### `POST /api/v1/chat`

Conversational search. Body: `{ messages: [{role, content}], last_search_params? }`.
Returns `{ content, search_results?, search_status?, effective_params?, search_error }`.

### `POST /api/v1/extract`

NL → structured params. Body: `{ query }`. Returns
`{ project, knowledge_type, error_codes, equipment, keywords, is_sentence }`.

## Documents {#documents}

Direct CRUD into the type indices (`src/kb/api/documents.py`).

| Method & path | Purpose |
|---|---|
| `GET /api/v1/documents/stats` | Doc counts aggregated by type / project / equipment / error code (powers the landing page) |
| `POST /api/v1/documents/{knowledge_type}` | Index one document → `201 { id }` |
| `POST /api/v1/documents/{knowledge_type}/_bulk` | Bulk index; surfaces all parse errors before running |
| `DELETE /api/v1/documents/{knowledge_type}/{doc_id}` | Delete by id → `204`, or `404` if absent |

`{knowledge_type}` is validated against the enum; the payload is discriminated to the
matching `AlarmDoc` / `SetupDoc` / `ExperienceDoc` model and validated against the
taxonomy.

## Ingest (file import)

Review-gated file → document pipeline (`src/kb/api/ingest.py`). Requires
`KB_LLM__API_KEY`. Full design in [Import Pipeline](architecture/import-pipeline.md).

| Method & path | Purpose |
|---|---|
| `POST /api/v1/ingest/upload` | Multipart upload → `202 { session_id }` |
| `POST /api/v1/ingest/scan` | Scan a server-side folder (under `scan_root`) → `202` |
| `GET /api/v1/ingest/sessions` | List sessions |
| `GET /api/v1/ingest/sessions/{id}` | Inspect a session (poll until `ready_for_review`) |
| `PUT /api/v1/ingest/sessions/{id}/documents/{idx}` | Edit a staged document |
| `PATCH /api/v1/ingest/sessions/{id}/documents/{idx}` | Accept / reject a staged document |
| `POST /api/v1/ingest/sessions/{id}/documents/accept-all` | Accept all staged docs |
| `POST /api/v1/ingest/sessions/{id}/commit` | Write accepted docs to ES |

Retry endpoints let you reprocess failed files (optionally forcing OCR).

## Feedback

| Method & path | Purpose |
|---|---|
| `POST /api/v1/search/feedback` | Record one 👍/👎 on a result → `202`. Observational only — never alters results |

Body: `{ doc_id, helpful, query_text?, knowledge_type?, project?, equipment?,
search_status? }`. See [Observability → Search feedback](observability.md#search-feedback).
